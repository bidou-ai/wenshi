# Wenshi 项目全面分析报告

更新时间：2026-09-08

## 1. 项目一句话说明

Wenshi 是一个面向温室水稻的移动协作机器人表型巡检项目。目标是让 AGV 沿温室通道行驶，JAKA 协作机械臂配合 D435 RGB-D 相机采集指定植株的图像和深度证据，再对 32 株水稻计算株高和有效穗数，并把原始证据、检测结果和人工复核结果保存下来。

项目不是单纯的 YOLO 训练项目，也不是单纯的机械臂控制项目，而是由以下部分组成的完整系统：

```text
温室布局与身份
    -> AGV 地图和路线
    -> 停车与安全互锁
    -> JAKA 姿态和相机采集
    -> Tag/株号确认
    -> 整株与稻穗视觉模型
    -> 株高/有效穗候选
    -> 人工复核
    -> 运行记录、后台查看和 CSV 导出
```

## 2. 当前正式范围

当前正式目标是四排、每排八株，共 32 株：

| 排 | 植株编号 | 观测组 |
| --- | --- | --- |
| `A` | `A-01` 至 `A-08` | `left-01` 至 `left-08` |
| `B-L` | `B-L-01` 至 `B-L-08` | `left-01` 至 `left-08` |
| `B-R` | `B-R-01` 至 `B-R-08` | `right-01` 至 `right-08` |
| `C` | `C-01` 至 `C-08` | `right-01` 至 `right-08` |

共 16 个观测组，每个观测组覆盖两株，每株计划采集 `left`、`center`、`right` 三个视角的 RGB-D 证据。

当前表型只做两项：

1. 株高。
2. 有效穗数。

当前不应把旧版 `rice` 识别、旧路线、倒车、J5 跟随或固定抵近原型当作现行表型流程。

## 3. 当前完成度结论

### 3.1 已有证据支持的完成项

- 32 株、16 个观测组的配置、调度和数据结构已经建立。
- AGV/JAKA/D435 的离线接口、预检、安全边界和现场测试入口已经存在。
- 现场八点示教流程已经修复并完成现场测试：8/8 点保存，机械臂逐点测试完成，控制响应记录为 `errorCode: 0`。
- 路线测试已有现场记录：路线能够运行，并记录过阻挡停止与恢复。
- 两套训练数据流程已经分开：整株模型和稻穗模型不会共用类别或发布目标。
- 数据规范化、标注、训练副本生成、按植株分组划分和模型发布保护已经实现。
- 单元测试和集成测试在最近一次检查中通过，且已有 `daily-check` 离线检查入口。

### 3.2 不能写成“正式完成”的项目

`phenotyping.enabled` 当前仍为 `false`。以下项目没有完整现场证据：

| 项目 | 状态 |
| --- | --- |
| 32 个 Tag 与株号映射 | 未完成，配置仍有 `tag_id: null` |
| Tag 尺寸、朝向和检测后端 | 未完成 |
| 各卡槽到水面的高度 | 未完成；已有部分测量信息不能替代 32 株记录 |
| 16 个停车组路线参数 | 未完成现场标定 |
| 三视角机械臂姿态 | 未完成现场验收 |
| RGB-D、相机内参、深度尺度、手眼关系 | 未形成完整现场证据 |
| 正式表型运动适配器 | 尚未完成现场验收 |
| 株高和有效穗精度阈值 | 尚未正式定义 |

现场教学、路线测试、机械臂测试和离线模型训练，都不能替代 32 株表型验收。

`yubei/data/`、`yubei/datasets/`、`yubei/training/` 和 `yubei/backups/` 是本地生成物，
已由 `.gitignore` 排除；原始数据和训练权重不得因整理而覆盖或删除。

## 6. 数据与模型现状

### 6.1 第一版数据

整株数据：

```text
yubei/data/plant/dataset_20260828_154448_562619
20 张，10 株，每株连续 2 张
```

稻穗数据：

```text
yubei/data/panicle/dataset_20260828_150142_729627
90 张，10 株，每株 9 张
正面 3 张、左侧 3 张、右侧 3 张
83 张已标注，7 张歧义或跳过，464 个稻穗框
```

整株副本可按需要转为竖直方向；稻穗保留原始横向方向。原始数据必须保留，旋转和训练副本不能覆盖原图。

### 6.2 第一版模型

| 模型 | 产物 | 结果 | 判断 |
| --- | --- | --- | --- |
| `rice_plant` | `yubei/training/plant/plant_20260906_101646/weights/best.pt` | mAP50 约 0.995，recall 1.0 | 可作基线，验证植株太少，不能正式放行 |
| `panicle` | `yubei/training/panicle/panicle_20260904_134044/weights/best.pt` | mAP50 约 0.499，mAP50-95 约 0.155 | 仍需补数据和错误分析 |

正确顺序是：

```text
独立测试集
-> 预测和人工错误分析
-> 针对性补拍真实数据
-> 第二轮训练
-> 用完全独立数据验证
-> 人工复核后再考虑发布
```

不能只看 mAP，也不能把稻穗检测框数量直接当成有效穗数。

## 8. 短期目标

按优先级排序：

1. 建立完全独立于现有 10 株数据的测试集，并按植株分组。
2. 分别验证整株模型和稻穗模型，形成漏检、误检、重复框、遮挡和小目标失败清单。
3. 针对真实错误补拍和补标，完成第二轮训练。
4. 定义模型放行标准：跨植株、跨视角、人工复核和有效穗计数误差都要满足要求。
5. 完成 32 个 Tag 的 ID、尺寸、朝向和株号映射。
6. 完成卡槽到水面的逐株测量和相机/深度/手眼标定。
7. 从一株、一视角、一观测组两株逐级验收，再扩大到 16 组。
8. 根据最终确认的现场规则决定是否纳入某一排；任何“最右一排不检查”的变化必须先写入配置、测试和验收清单，不能只停留在聊天决定。

## 9. 长期目标

长期交付标准不是“程序能启动”，而是：

- 32 株身份可追溯且每株恰好覆盖一次。
- AGV 能按安全路线稳定到达 16 个观测组。
- JAKA 能在安全互锁下执行三视角采集。
- RGB-D 证据完整、时间和株号对应正确。
- 株高和有效穗数有明确算法、人工复核和误差标准。
- 现场中断、急停、断流和补采都有可恢复流程。
- 后台可以追溯每次运行的原图、模型版本、配置版本和人工修改。
- 发布模型、配置和现场标定均有版本、校验值和回滚记录。

## 10. 项目判断

项目已经从“多个原型脚本”进入“正式系统骨架和第一版模型基线”阶段，但还没有进入“正式无人/自动表型巡检可用”阶段。现在最重要的工作是把数据验证、现场标定和验收证据补齐，而不是继续堆叠入口或直接打开正式表型开关。
