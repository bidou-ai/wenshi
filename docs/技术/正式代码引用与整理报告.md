# 正式代码引用与整理报告

## 本轮边界

本轮没有删除 `yubei/`，也没有把历史现场证据移动出 `runtime/field_tests/`。新的一键株高工具放在 `app/wenshi_patrol/height_test/`，与原正式巡检和旧表型控制器隔离；`phenotyping.enabled` 仍为 `false`。

## 保留模块和原因

| 模块 | 状态 | 当前消费者/理由 |
| --- | --- | --- |
| `patrol_controller.py` | 保留 | `scripts/start_wenshi.sh` 默认巡检入口及现有单元测试 |
| `route_controller.py`、`control/` | 保留 | 正式路线数学、安全策略和路线测试 |
| `jaka.py`、`agv.py`、`arm_controller.py` | 保留 | 硬件客户端和已有现场测试，不能在无证据时改名或移动 |
| `phenotyping/config.py`、`schema.py`、`preflight.py` | 保留/兼容 | 旧正式表型预检仍验证 32 株和 16 组；正式入口继续禁用 |
| `phenotyping/capture_controller.py` | 保留/兼容 | 已有三视角 burst、安全回撤和单元测试；新工具通过窄接口复用概念，不直接导入运动客户端 |
| `vision/` | 保留 | 现有检测、质量、几何和存储调用链 |
| `height_test/` | 新增/现场通道 | setup、RGB-D、双 YOLO、M0-M5、证据、runner、replay |
| `yubei/` | 保留 | 数据采集、标注、训练和 Windows D435 服务；本轮不整理、不删除 |

## 未做的删除

`near_capture.py`、`target_follow.py`、`target_task.py`、`patrol_target_runtime.py`、`fixed_approach.py` 等仍有历史入口、文档或测试引用。当前没有足够证据证明删除或移动不会改变既有现场流程，因此保留原路径，后续单独提交迁移并保留兼容导入。

## 验证边界

- 新代码不导入 `yubei` 的训练模块；相机只使用稳定的 `HttpCameraClient` 数据边界。
- replay/report 路径不创建 AGV/JAKA 客户端。
- 正式巡检、dashboard、旧 field test 和 `yubei` 单元测试保持原入口。
- 任何旧文件的删除必须先更新本报告、生成引用图、跑全量测试并由现场回归确认；本轮不做破坏性整理。
