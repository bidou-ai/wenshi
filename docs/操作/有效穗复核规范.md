# 有效穗复核规范

## 候选状态

有效穗是能够看清并确认已经长出的穗子。每个候选保留 `candidate_id`、视角、边界框、可选置信度和深度，以及 `confirmed`、`suspected`、`occluded`、`duplicate`、`deleted` 状态。三视角候选不能直接相加。

复核员可合并同一穗的跨视角候选、拆分误合并组、解除关联、补充人工候选、删除误检或更改状态；所有操作写入历史记录。空间自动合并只有在已提供共同三维参考时才可使用，且仍需人工复核。

## 计数证据

`summarize_panicles()` 的 `automatic_count` 是未删除、非人工候选按 `panicle_group_id` 去重后的组数；未分组候选各算一组。`reviewed_count` 只统计其中至少有一个自动候选为 `confirmed` 的组。人工新增候选保留为复核证据，但不伪装为自动候选。正式数量以人工确认的 `reviewed_count` 为准。

```python
from wenshi_patrol.phenotyping.effective_panicles import (
    PanicleReview, apply_review_operation, build_candidates,
    merge_panicles, summarize_panicles,
)

review = PanicleReview(build_candidates("A-01", {
    "left": [{"bbox": [10, 20, 40, 90], "score": 0.86}],
    "center": [{"bbox": [14, 22, 44, 92], "score": 0.79}],
}))
merge_panicles(review, ["left-001", "center-001"], "panicle-001")
apply_review_operation(review, "status", candidate_ids=["left-001"], status="confirmed")
summary = summarize_panicles(review, automatic_count=1, reviewed_count=1)
```

该示例的两个跨视角候选属于同一组，因此自动和人工确认计数都为 1，而不是把两个视角相加为 2。
