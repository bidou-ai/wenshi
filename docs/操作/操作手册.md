# 操作手册

## 范围与入口

当前表型范围仅为**株高**和**有效穗数**。目标布局为四排各八株：`A`、`B-L`、`B-R`、`C`，共 32 株；观测组为 `left-01` 至 `left-08`、`right-01` 至 `right-08`，共 16 个。每个观测组覆盖通道两侧两株，每株计划采集 `left`、`center`、`right` 三视角 RGB-D 证据。

在当前配置下，`phenotyping.enabled` 为 `false`，Tag、停车点、表型姿态、相机和水位补偿均未完成现场标定。表型入口只能用于预检或模拟，不得用于驱动 AGV、JAKA 或 D435：

```bash
./scripts/start_wenshi.sh phenotype --help
PYTHONPATH=app:. python3 -m wenshi_patrol.phenotype_controller --check --config config/wenshi.yaml
```

现场教学、路线和机械臂测试使用 `./scripts/start_field_test.sh`；它们不是 32 株表型验收。后台使用 `./scripts/start_dashboard.sh`，仅提供结果查看和 CSV 导出，不提供运动控制。

## 正式任务前的顺序

1. 按[标签映射与现场确认](标签映射与现场确认.md)逐株确认 32 个 `tag25h7` Tag、实际边长、朝向和高度。
2. 按[标定说明](../技术/标定说明.md)标定 16 个停车组的路线参数、三视角表型姿态、相机与水面补偿。
3. 使用[现场验收清单](现场验收清单.md)从单 Tag、单视角和一停车组两株，逐步扩大到 16 组和 32 株。
4. 通过预检后，才由后续已经验收的表型运动适配器执行正式采集；当前仓库没有该适配器的现场验收结论。

不得把旧 `rice` 目标抵近、倒车、J5 跟随或固定抵近当作表型采集流程。

## 采集与复核

每株的运行数据应位于 `runtime/runs/run_<timestamp>/plants/<plant_id>/`。每个视角保存 RGB、可用的深度图和 `frame.json`，两项表型分别写入 trait JSON。详细结构见[表型数据结构](../技术/表型数据结构.md)。

- 株高沿卡槽/水面基准、同一根茎秆中心线、穗轴到最高穗顶的三维路径计算；候选和人工复核遵循[株高复核规范](株高复核规范.md)。
- 有效穗候选必须跨视角合并；正式数量以人工确认的证据计数为准，遵循[有效穗复核规范](有效穗复核规范.md)。
- 缺失深度、Tag 不匹配、遮挡、路径歧义或未完成补偿必须保留原因并进入复核或补采，不能猜测数值或株号。

## 停止与故障处理

人员进入工作区、急停、报警、定位过期、阻挡、相机断流或姿态异常时，先执行实体急停并确认底盘和机械臂停止，再输入 `stop` 并排查。不得通过配置绕过预检、报警或姿态限制。完整约束见[安全约束](安全约束.md)。

Windows D435 服务的健康检查为 `http://192.168.192.203:18080/health`；地址来自当前配置，实际连通性必须现场检查。服务存在但没有有效帧和端口不可达是不同故障，应分别检查 D435、Windows 进程、防火墙、网卡和服务日志。

## 当前训练数据采集

当前训练阶段不需要 Tag。Tag 以后用于正式植株身份确认，不参与这两套模型的数据采集、标注或训练。

两个模型必须分开采集和训练：

```text
整株水稻：rice_plant
稻穗：panicle
```

推荐每株或每个目标拍摄三组 RGB 角度：正面 `center`、左斜侧 `left`、右斜侧 `right`。整株图片应尽量包含完整地上部分；稻穗图片应清楚包含穗部，允许一张图有多个稻穗。每套数据要覆盖远近、光照、遮挡、不同生长状态和不同背景，不能只连续拍同一张画面。

### 采集整株数据

```bash
./yubei/start_yubei.sh capture-plant
```

预览中按回车保存当前照片，输入 `q` 结束。这个命令不读取 Tag、不连接 AGV/JAKA，只访问 D435 图像服务，数据保存在 `yubei/data/plant/`。

### 采集稻穗数据

```bash
./yubei/start_yubei.sh capture-panicle
```

按同样方式保存，数据保存在 `yubei/data/panicle/`。完成一套采集后进入本地标注网页：

```bash
./yubei/start_yubei.sh label yubei/data/plant/dataset_时间
./yubei/start_yubei.sh label yubei/data/panicle/dataset_时间
```

整株数据只框 `rice_plant`，稻穗数据只框 `panicle`。标注保存后分别准备和训练：

```bash
./yubei/start_yubei.sh prepare-plant yubei/data/plant/dataset_时间
./yubei/start_yubei.sh train-plant

./yubei/start_yubei.sh prepare-panicle yubei/data/panicle/dataset_时间
./yubei/start_yubei.sh train-panicle
```

训练会检查 `data.yaml` 的类别是否与模型类型一致；模型不会自动发布。确认训练结果和验证指标后，才使用带 `--confirm` 的模型发布命令。

## 本次数据的标准处理顺序

本次已采集数据应先保留原始目录，不在原图上直接改方向。当前两套原始会话为：

```text
yubei/data/plant/dataset_20260828_154448_562619
yubei/data/panicle/dataset_20260828_150142_729627
```

先生成竖直方向的训练副本：

```bash
./yubei/start_yubei.sh normalize-plant yubei/data/plant/dataset_20260828_154448_562619
./yubei/start_yubei.sh normalize-panicle yubei/data/panicle/dataset_20260828_150142_729627
```

整株命令顺时针旋转 90 度，稻穗命令保持原始方向，原始图片不变。确认生成的图片方向正确后，只在 `dataset_normalized_*` 目录上标注：

```bash
./yubei/start_yubei.sh label yubei/data/plant/dataset_normalized_dataset_20260828_154448_562619
./yubei/start_yubei.sh label yubei/data/panicle/dataset_normalized_dataset_20260828_150142_729627
```

整株每张图片只框 `rice_plant`；稻穗每个独立可辨认的稻穗分别框 `panicle`。严重遮挡、边界无法判断的图片标记歧义，不要强行画框。

标注完成后，按本次采集顺序防止同一株泄漏到验证集：

```bash
./yubei/start_yubei.sh prepare-plant yubei/data/plant/dataset_normalized_dataset_20260828_154448_562619
./yubei/start_yubei.sh train-plant

./yubei/start_yubei.sh prepare-panicle yubei/data/panicle/dataset_normalized_dataset_20260828_150142_729627
./yubei/start_yubei.sh train-panicle
```

准备程序使用固定连续分组：整株每 2 张视为同一株，稻穗每 9 张视为同一株。它会把同一株的全部图片放进同一分区，避免训练结果虚高。当前只有 10 株，第一版训练只能用于流程验证和发现错误，不能作为最终精度结论。
