# 机械臂双株稻穗识别展示 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付独立 `arm_demo.sh`，让固定底盘上的 JAKA 按 10 个示教姿态循环观察左侧两株水稻，并以同帧双画面实时展示原始 RGB 与稻穗 YOLO 候选框。

**Architecture:** `arm_demo_setup.py` 独占示教 schema 和证据；`arm_demo_vision.py` 独占 RGB latest-frame、单模型推理与双栏画布；`arm_demo.py` 编排 JAKA 状态机、交互 setup、OpenCV 主线程和 CLI。Shell 入口只获取共享硬件锁并调用独立模块，不启动 AGV、ROS 或 RViz。

**Tech Stack:** Python 3.10、pytest、OpenCV、NumPy、PyYAML、Ultralytics YOLO、现有 JAKA TCP 客户端、Bash。

**Spec:** `docs/superpowers/specs/2026-09-19-机械臂双株稻穗识别展示设计.md`

## Global Constraints

- 只控制 JAKA；不得导入、实例化或连接任何 AGV 客户端。
- 微扫只使用 10 个现场示教的绝对姿态，不生成关节偏移，检测结果没有运动权限。
- 任意运动 false/异常必须显式 `stop_program` 并进入 ERROR；pause/quit 不自动回家。
- 相机和推理只保留最新帧；左右画面来自同一帧；所有 OpenCV GUI 调用只在主线程。
- 连续展示速度硬上限为过渡 18、抵近 9、微扫 4 deg/s；验收模式全部 5 deg/s；加速度最高 60 deg/s2。
- 默认模型是现有 panicle `best.pt`，界面只能称检测候选框，不能称有效穗数。
- 运行数据仅写 `runtime/arm_demo/`，只与其他 Demo 共享 `wenshi-demo-hardware.lock`。
- 手工代码编辑使用 `apply_patch`，先写失败测试，再实现，再运行回归。
