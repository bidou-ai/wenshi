# 项目审查与双人协作文档实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 根据当前仓库、数据、模型、现场日志和既有文档，形成一份项目全面分析报告与一份双人错峰调试协作手册。

**Architecture:** 分析报告负责建立唯一的项目事实视图，按目录、状态、目标和清理建议组织；协作手册负责建立两人共享上下文、交接、现场安全、代码修改和 Git 同步规则。两份文档互相链接，但不重复维护同一套技术细节。

**Tech Stack:** Markdown、Git、现有 Wenshi Python/ROS2/YOLO 工具链。

**Spec:** 用户已确认的“项目全面分析报告 + 双人协作与错峰调试手册”设计。

## Global Constraints

- `docs/` 下新 Markdown 使用中文名称。
- 根目录 `README.md` 保持 GitHub 入口并加入新文档链接。
- 不删除现有文件；删除候选必须先确认无引用、无追溯价值。
- 只把有代码、日志、数据或配置证据支持的内容写成已完成。
- 明确区分离线验证、现场硬件验证、模型基线和正式放行。
- 现场调试必须先遵守 `docs/操作/安全约束.md`。

### Task 1: 生成项目全面分析报告

**Files:**
- Create: `docs/技术/项目全面分析报告.md`

- [ ] 汇总项目目标、现行范围、系统链路、目录职责、文档分类、数据与模型状态、现场证据、风险、清理建议以及短期/长期路线。
- [ ] 对可删除内容只给出候选，不执行删除。
- [ ] 交叉检查报告中的路径、模型指标和布局与现行 README、项目状态文档一致。

### Task 2: 生成双人协作与错峰调试手册

**Files:**
- Create: `docs/操作/双人协作与错峰调试手册.md`

- [ ] 定义操作者 A/B、会话前缀、任务锁、交接记录、现场/离线边界、代码修改流程和 Git 同步流程。
- [ ] 提供可复制的对话开场模板、交接模板、现场记录模板和故障报告模板。
- [ ] 明确禁止并行修改同一文件、禁止无证据宣称完成、禁止远程命令代替现场安全确认。

### Task 3: 更新 GitHub 入口并验证

**Files:**
- Modify: `README.md`

- [ ] 在现行文档表中加入两份文档入口。
- [ ] 检查 Markdown 链接、路径、状态表述和 Git diff。
- [ ] 运行 `git diff --check`，并运行项目现有测试或至少运行文档交付相关测试。
