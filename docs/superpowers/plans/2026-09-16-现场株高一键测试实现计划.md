# 现场株高一键测试实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不影响现有正式巡检和 `yubei` 数据流程的前提下，交付一个支持现场 setup、JAKA 单站测试、AGV 全路线测试、RGB-D/双 YOLO/多株高方法、replay 和报告的一键工程工具。

**Architecture:** 新增独立 `app/wenshi_patrol/height_test/` 子系统，运动编排、RGB-D 采集、模型推理、Tag/几何算法、存储和报告分别隔离。算法只消费帧和姿态快照，不导入 AGV/JAKA 运动客户端；runner 只负责安全顺序和停止。现场结果写入 `runtime/height_tests/`，`replay` 只读这些证据。

**Tech Stack:** Python 3.10、NumPy、OpenCV、PyYAML、现有 `ultralytics`；可插拔 `pupil_apriltags`/`apriltag` 后端；不把 Open3D、PlantCV、SciPy、scikit-image 作为第一阶段硬依赖。

**Spec:** `docs/superpowers/specs/2026-09-16-现场株高一键测试与24株工程化设计.md`

## Global Constraints

- 正式检测范围为 A、B-L、B-R 共 24 株；C-01..C-08 保留 Tag，但 `excluded_from_detection=true`，不得触发检测或表型计算。
- 左侧 `left-01..08` 各测 A 与 B-L 两株；右侧 `right-01..08` 各测 B-R 一株；共 16 个现场停车点。
- `phenotyping.enabled` 保持 `false`；测试不得写入 `runtime/runs/run_*`，只写 `runtime/height_tests/`。
- 原始 RGB、depth、帧元数据、模型输出和人工输入必须保留；处理结果写新文件，不覆盖训练数据或历史现场证据。
- M0 YOLO 框高只作诊断；正式候选以水面到最高穗顶的垂直高度为主，茎秆三维弧长为诊断值。
- 所有硬件动作可被 `stop`/`q` 中止；异常时先实体急停，再软件停止；算法代码不能直接发送运动命令。
- 每个任务结束时运行任务列出的定向测试并提交一个小提交；不重置或覆盖工作区中已有未提交修改。
