# 32 株表型与文档收敛设计

## 目的与范围

将当前正式表型范围从 24 株、12 个停车观测组迁移到 32 株、16 个停车观测组，并收敛项目文档。正式任务仍只包含株高和有效穗数；旧的 rice/flower 检测、倒车、J5 跟随、固定抵近仅作为历史原型保留。

本设计不接入真实表型运动，不改动 AGV、JAKA 或 D435 的现场控制权限。`phenotyping.enabled` 必须继续为 `false`，直到 Tag、停车位、相机和机械臂标定均有现场证据。

## 已确认的布局

植株区域、通道关系和每次停车两株的模型保持不变；每排从 6 株扩展到 8 株：

```text
A-01..A-08       B-L-01..B-L-08
B-R-01..B-R-08   C-01..C-08
```

左通道观测组为 `left-01..left-08`，依次覆盖 `A-n` 与 `B-L-n`；右通道观测组为 `right-01..right-08`，依次覆盖 `B-R-n` 与 `C-n`。合计 32 株、16 个停车观测组。每个观测组仍要求恰好两株、每株恰好被覆盖一次。

## 代码与配置

1. 将表型配置常量从 24/12 改为 32/16。
2. 扩展 `config/wenshi.yaml` 中四排植株、Tag 占位项和 16 个停车观测组；新增项继续使用 `null` 标定值。
3. 更新调度器固定组 ID 为左右各 8 个，并保持左后右的稳定顺序。
4. 用真实编号与配对更新 schema、预检和调度测试；新增 32 株完整覆盖、漏株、重复株和重复停车组回归测试。
5. 不改变单株三视角采集、存储、复核、后台 API 和“停车位两株完成后才能恢复路线”的控制协议。

## 文档信息架构

根目录 `README.md` 保留该 GitHub 标准文件名，内容改为中文项目首页：当前范围、系统边界、硬件、入口、验证、现场状态和文档导航。它不得把离线逻辑和现场硬件验收混为一谈。

`docs/` 只保留中文文件名。现行文件按操作和技术用途组织，至少包括：


`OPERATIONS.md` 与 `USER_MANUAL.md` 合并为一份操作手册。历史计划、设计、旧视觉训练和迁移说明移入归档并标明其性质。根目录、`yubei/`、`windows/`、`models/` 等目录外的 Markdown 不受“中文文件名”约束，但其首页链接必须准确说明是否属于当前流程。

文档维护约定写入根目录 `AGENTS.md`：不重复创建说明，状态变化时同次更新现行文档，历史资料优先归档而非直接删除。

## 初步硬件设计

初步设计文件应准确画出并说明以下链路：AGV 底盘、JAKA 机械臂、机械臂末端 D435、Windows 相机服务、机器人内部网络、Ubuntu/VMware 双网络路径、32 个 Tag 和四排八株布局。

Tag 固定在所属水稻的卡槽前，允许卡槽上方朝天或侧面安装；最终 Tag 尺寸、朝向、ID 到株号映射、距水面高度、遮挡防护和检测后端均为现场待标定项。设计必须列出这些开放项，不得填入猜测数值。
