# 机械臂双株稻穗识别展示设计

日期：2026-09-19

状态：用户已确认，进入实现

## 1. 目标

新增完全独立的 `arm_demo.sh`，用于底盘固定、两株水稻均位于机器人左侧的专家
展示。演示期间只控制 JAKA 机械臂，不连接或控制 AGV。D435 画面在电脑上以一个
全屏双栏窗口显示：左侧为无标框原图，右侧为同一帧的稻穗检测候选框。

展示不进行株高测量，不把检测框数量宣称为有效穗数，不自动保存图片或视频，
检测结果也不得驱动机械臂。

## 2. 独立边界

新增入口、配置、setup 和运行目录：

```text
arm_demo.sh
config/arm_demo.yaml
app/wenshi_patrol/arm_demo.py
app/wenshi_patrol/arm_demo_setup.py
app/wenshi_patrol/arm_demo_vision.py
runtime/arm_demo/
  setup_<timestamp>/
  demo_setup.json
  photos/
```

该入口不读取 `runtime/demo/` 或 `runtime/9.18/` 作为运行依赖，不启动 ROS、RViz、
地图或相机桥，不创建 AGV 客户端。它与其他演示仅共享
`${TMPDIR:-/tmp}/wenshi-demo-hardware.lock`，防止多个程序同时控制 JAKA。

## 3. 现场示教

setup 只连接 D435 和 JAKA 状态接口，不发送任何运动命令。操作者使用示教器依次
摆好并确认以下 10 个绝对关节姿态：

```text
home_safe
left_clearance
rice1_pre
rice1_center
rice1_scan_a
rice1_scan_b
rice2_pre
rice2_center
rice2_scan_a
rice2_scan_b
```

每个姿态连续读取三次关节角并验证最大波动不超过 `0.20 deg`，同时记录 TCP 和
当前 D435 照片。草稿每完成一个姿态立即原子保存，可通过 `--resume` 恢复。

`scan_a`、`scan_b` 相对同株 `center` 的 TCP 平移不得超过 `120 mm`，任一关节差
不得超过 `15 deg`。这些检查只能发现明显误示教，不能代替现场碰撞确认。

发布文件使用独立 schema `wenshi_arm_panicle_demo`，loader 必须校验有限六轴关节、
有限 TCP、照片目录边界、完整姿态集合和微扫范围。

## 4. 动作路线

每株执行：

```text
left_clearance
-> riceN_pre
-> riceN_center       hold 1.5 s
-> riceN_scan_a       hold 1.0 s
-> riceN_center       hold 0.4 s
-> riceN_scan_b       hold 1.0 s
-> riceN_center       hold 1.5 s
-> riceN_pre
-> left_clearance
```

每轮从 `home_safe` 出发并回到 `home_safe`。奇数轮顺序为水稻 1、水稻 2；偶数轮
顺序为水稻 2、水稻 1。两株之间必须经过 `left_clearance`，禁止从一株近景姿态
直接移动到另一株。

不通过当前关节角加减生成扫描姿态，不进行随机偏移，不根据检测框跟随目标。

速度采用硬上限：

- `--test-once`：全部动作最高 `5 deg/s`；
- 连续展示公共过渡最高 `18 deg/s`；
- 抵近姿态最高 `9 deg/s`；
- 微扫姿态最高 `4 deg/s`；
- 加速度最高 `60 deg/s2`。

配置可以降低速度，但不能突破上述上限。

## 5. 运动状态机

状态为 `READY`、`RUNNING`、`HOLD`、`RECOVERING`、`ERROR`、`STOPPED`。

启动时必须读取新鲜关节状态，并确认当前六轴均在 `home_safe` 的 `3 deg` 范围内；
未知起始姿态拒绝自动运动。每次运动前检查停止标志、连接和目标白名单，运动后再次
确认状态新鲜且到位。

`pause`、窗口关闭、相机过期或检测线程连续失败时立即调用 `stop_program` 并保持
当前位置，不自动回家。普通暂停后，`home` 沿当前已示教边反向回到上一个确认点，
再按 `scan -> center -> pre -> clearance -> home_safe` 回撤。当前位置无法证明处于
已示教边的窄走廊时拒绝自动恢复。

`joint_move` 返回 false、停滞、超时、关节状态过期或连接断开时必须额外显式调用
`stop_program` 并进入 `ERROR`。ERROR 不允许自动恢复，由操作者使用示教器处理。

## 6. 视觉流水线

使用现有训练权重：

```text
yubei/training/panicle/panicle_20260904_134044/weights/best.pt
```

只加载 `RiceMarkerDetector` 稻穗模型，不加载整株模型。默认置信度阈值 `0.25`，
类别限制为 `panicle`。启动时先完成模型加载、空白帧预热和第一张有效相机帧，随后
才允许机械臂进入 READY。

视觉采用三个职责边界：

1. RGB 获取线程轮询 D435 HTTP `/health` 和 `/snapshot.jpg`，只保留最新帧；
2. 推理线程只消费最新未处理帧，输出原图、标框图、候选数量、延迟和时间戳；
3. OpenCV 主线程独占 `namedWindow/imshow/waitKey/destroyWindow`。

所有队列容量为 1，慢帧直接丢弃，不积压。左右两栏必须来自同一次推理输入，不能
把旧框画到新原图。相机或结果超过 `1.0 s` 未更新时判定过期。

## 7. 展示界面

只创建一个 OpenCV 窗口，默认全屏。画布为左右等宽、同比例、带 letterbox 的两块
图像：

- 左标题：`LIVE RGB`，不含检测框；
- 右标题：`PANICLE DETECTION`，显示候选框和置信度；
- 右上角可显示 `CANDIDATES N` 和推理延迟，但不得显示为有效穗数；
- 底部只保留一行当前机械臂状态和按键提示，不增加地图、图表或控制面板。

按键：

- `Space`：READY 开始；RUNNING 立即暂停；
- `H`：从 HOLD 按已教路径安全回撤；
- `P`：人工保存当前双栏画面；
- `Q` 或 `Esc`：立即停止并退出，不自动回家。

关闭窗口等价于 Q。截图只有人工按 P 才写入 `runtime/arm_demo/photos/`。

## 8. 命令接口

```bash
./arm_demo.sh --setup
./arm_demo.sh --setup --resume runtime/arm_demo/setup_<timestamp>
./arm_demo.sh --dry-run
./arm_demo.sh --test-once
./arm_demo.sh
```

`--dry-run` 只校验配置、模型和 setup，不连接相机或 JAKA，不创建 GUI。
`--test-once` 使用全程低速，完成两株一轮并回到 home 后停止循环，界面继续显示。

## 9. 验证范围

自动测试覆盖 setup 发布/恢复/篡改/越界、固定动作顺序和交替轮次、速度硬上限、
起始 home 门禁、pause 后不补发动作、失败后 stop 和 ERROR、按已教路径回撤、
latest-frame 丢帧、同帧双画面、过期检测、主线程 UI 组合、入口路径隔离、共享锁、
dry-run 无硬件连接以及全项目回归。

软件测试不能证明实际路径无碰撞。现场必须先用 `--test-once` 和 `5 deg/s`，由一人
手持实体急停，对每条边进行正反向验证后才能运行连续展示。
