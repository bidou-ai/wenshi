# 9.18 独立无 Tag 专家展示设计

日期：2026-09-18

状态：用户已确认设计，待实现

## 1. 目标

为新场地提供一个与 `wenshi.sh` 展示效果一致、但数据和业务逻辑完全隔离的
专家展示入口：

```bash
./9.18.sh
```

新场地有水稻但没有 AprilTag，地图需要到场后重新扫描，水稻排数和观察点数量
当前未知。系统不得假设旧场地的 24 个观察点、A/B/C 分区、Tag 编号、LM1-LM4
路线或旧地图仍然有效。

展示仍包含以下行为：

- RViz 实时显示新地图、AGV 位姿、示教路线、观察点和 D435 RGB；
- AGV 沿现场示教路线连续巡航；
- 每轮随机选择若干水稻观察点；
- 到观察点前减速，到点后停稳并自动校正朝向；
- JAKA 从 `home_safe` 伸向该点对应的 `left` 或 `right` 姿态，停留后收回；
- 终端支持 `pause`、`start`、`photo`、`status`、`stop`、`q`；
- 不运行 YOLO，不做株高监测，不自动保存检测数据。

## 2. 独立边界

新 Demo 与旧 Demo 采用独立入口、模块、配置、地图快照、setup、照片和临时日志：

```text
9.18.sh
config/9.18.yaml
config/9.18.rviz
app/wenshi_patrol/demo_918.py
app/wenshi_patrol/demo_918_setup.py
runtime/9.18/
  site/map-<sha256前12位>.smap
  setup_<timestamp>/
  demo_setup.json
  photos/
```

`9.18.sh` 不调用 `wenshi.sh`，新 Python 模块不读取
`runtime/demo/demo_setup.json` 作为运行时依赖，也不写入 `runtime/demo/` 或
`runtime/height_tests/`。新旧 Demo 可以复用已经验证的底层设备客户端、路线数学、
地图解析和 JAKA 通信代码，但不能共享场地业务配置。

两套 Demo 必须使用同一个硬件互斥锁。数据独立不意味着可以同时控制 AGV/JAKA；
任一入口运行时，另一个入口应拒绝启动。

## 3. 地图导入

现场扫描完成后执行：

```bash
./9.18.sh --setup --map /path/to/new-site.smap
```

setup 先以结构化 JSON 方式校验 `.smap` 的 header、范围和分辨率，再复制到本次
`setup_<timestamp>/map.smap` 证据目录。发布成功时，程序按 SHA-256 生成不可变的
`runtime/9.18/site/map-<sha256前12位>.smap`，然后原子替换 `demo_setup.json`。
后续运行只读取 setup 指向的快照，源文件被移动或覆盖不会改变已发布 Demo；新
setup 中止或校验失败也不会破坏上一份可运行地图。

地图用于 RViz 占据栅格显示，不要求其中预先存在 LM1-LM4 或任何固定名称的站点。
巡检路线由 setup 读取 AGV 实时定位姿态得到。

重新导入不同地图会创建新的 setup 证据目录；旧地图的路线和观察点不能静默复用。

## 4. 动态现场 Setup

setup 可中止、可通过 `--resume DIR` 恢复，草稿每完成一步立即原子写盘。setup
只读取 D435、AGV 状态和 JAKA 关节角，不发送 AGV/JAKA 运动命令。

### 4.1 操作员与路线模式

setup 询问操作员编号和路线模式：

- `shuttle`：单排或开放路线，按示教顺序走到末端后按逆序返回；
- `loop`：闭环路线，最后一个锚点连接回第一个锚点。

路线模式记录后恢复 setup 时不得改变。两种模式都至少需要两个路线锚点。

### 4.2 路线锚点

操作者输入锚点数量，然后手动把 AGV 驶到安全路线的各个关键位置。每个
`R-01..R-N` 在确认 `is_stop=true`、定位新鲜且无急停/阻挡/报警后读取
`x/y/angle`，拍摄一张 D435 证据照片，并在照片后再次读取位姿。位置变化超过
0.02 m 或朝向变化超过 2 度时拒绝保存。

相邻锚点距离必须大于 0.20 m。`loop` 的首尾距离也必须大于 0.20 m。程序只按
操作者给出的顺序连线，不根据障碍物自动猜测通路。

### 4.3 水稻观察点

操作者输入本次要展示的观察点数量，数量至少为 1，不设固定排数。程序依次登记
`P-01..P-N`：

- AGV 实时停车位姿和二次稳定性确认；
- 当前 D435 证据照片；
- 机械臂观察侧 `left` 或 `right`；
- 可选备注。

观察点必须能投影到某条示教路线段，横向距离不超过配置的 0.25 m。超过时拒绝
发布，要求补充路线锚点或重新登记观察点，不自动猜测路线。

系统不登记 Tag，不要求标定板照片，不包含 Tag family、Tag size 或植株 ID 映射。

### 4.4 机械臂姿态

需要且只需要 `home_safe`、`left`、`right` 三个姿态。setup 默认从已发布的旧
Demo setup 中一次性复制这三个姿态，并把关节值和来源摘要写入新草稿；复制完成
后新 Demo 不再读取旧文件。

旧姿态缺失或操作者选择重录时，沿用当前短连接读取方式：操作者通过示教器摆好
姿态，程序只读取 JAKA 关节角，不主动移动机械臂。

## 5. 发布数据

发布文件 `runtime/9.18/demo_setup.json` 使用独立 schema：

```json
{
  "schema_version": 1,
  "kind": "wenshi_918_expert_demo",
  "map": {
    "path": "site/map-e3b0c44298fc.smap",
    "sha256": "64位十六进制摘要"
  },
  "route": {
    "mode": "shuttle",
    "anchors": {
      "R-01": {"pose": {"x": 0, "y": 0, "angle": 0}}
    },
    "order": ["R-01", "R-02"]
  },
  "observations": {
    "P-01": {
      "pose": {"x": 0, "y": 0, "angle": 0},
      "arm_view": "left",
      "photo": "setup_20260918_150000/observations/P-01.jpg"
    }
  },
  "viewpoints": {
    "home_safe": {"joint": [0, 0, 0, 0, 0, 0]},
    "left": {"joint": [0, 0, 0, 0, 0, 0]},
    "right": {"joint": [0, 0, 0, 0, 0, 0]}
  }
}
```

loader 必须校验 schema、地图 SHA-256、所有照片在 `runtime/9.18` 边界内、有限
位姿、唯一名称、路线距离、观察点到路线距离以及三个有限的六轴关节姿态。

## 6. 运行路线

### 6.1 每轮选点

若观察点数量为 1 或 2，每轮选择全部；数量为 3 时选择 3 个；数量大于 3 时，
每轮随机选择 3 到 `min(5, N)` 个且不重复。随机结果打印在终端并发布到 RViz。

### 6.2 路线组装

每轮把选中的观察点按其在路线上的投影顺序插入路线：

- `loop`：按锚点顺序闭环一圈；
- `shuttle`：正向到末端，再反向回到起点，构成一轮。

同一个观察点在一轮中只观察一次。返程经过已经观察的点时不停留伸臂。

程序从当前位置投影到最近的本轮路线段接入，离路线超过 0.25 m 时拒绝自动运动。

### 6.3 速度与观察动作

与当前 `wenshi.sh` 使用同一组已验证参数：

- 巡航速度上限 0.18 m/s；
- 距目标最后 0.60 m 逐步减速，最低 0.04 m/s；
- 路线横向硬偏差 0.25 m；
- 到观察点后原地对中到 3 度以内，对中超时 8 s；
- 对中期间位置偏差不得超过 0.15 m；
- JAKA 观察速度 50 deg/s，收回速度 60 deg/s，加速度 80 deg/s2；
- 观察停留 2 s，然后回 `home_safe`。

观察顺序固定为：

```text
AGV停止 -> is_stop确认 -> 3度对中 -> 再次确认位置/朝向/is_stop
-> home_safe -> 对应left/right -> 停留2s -> home_safe -> 继续巡航
```

## 7. RViz 与拍照

`config/9.18.rviz` 使用独立主题：

```text
/demo918/map
/demo918/agv_pose
/demo918/markers
/demo918/state
/demo918/camera/color
```

marker 同时显示路线锚点、完整路线、全部观察点和本轮随机点。D435 桥只发布实时
RGB；只有操作者输入 `photo` 时才写入 `runtime/9.18/photos/`。

## 8. 安全与失败处理

- setup 和运行模式在连接任何硬件前获取共享硬件锁；
- AGV 状态过期、非有限位姿、急停、阻挡、报警或刹车时立即停止；
- 行驶和原地对中的速度命令与 `pause/stop` 使用同一状态锁，暂停后不得补发命令；
- AGV 未停稳、位置超差或朝向超过 3 度时禁止伸臂；
- 停止后只有确认 AGV 安全停稳才允许机械臂回撤；
- 相机失败阻止需要相机的正常启动，但 `--no-camera` 可用于无相机调试；
- `--dry-run` 不连接 AGV、JAKA、D435，不启动 ROS/RViz；
- 任何校验失败都保留 setup 草稿和证据，不覆盖已发布 setup。

## 9. 命令接口

```bash
# 第一次：地图扫描完成后
./9.18.sh --setup --map /path/to/new-site.smap

# 中断后继续
./9.18.sh --setup --resume runtime/9.18/setup_<timestamp>

# 本地完整性检查
./9.18.sh --dry-run

# 专家展示
./9.18.sh
```

支持与旧入口一致的 `--no-rviz`、`--no-camera`、`--setup-file` 和 `--photos`。
`--map` 只允许用于创建新 setup，恢复时使用草稿中已经固定的地图快照。

## 10. 验证范围

自动测试覆盖：

- 新旧脚本、配置、setup 和照片目录互不读写；
- 新 setup 不包含或要求任何 Tag 字段；
- 动态 1、2、3、5 个观察点均能发布和选点；
- loop 和 shuttle 路线段顺序正确；
- 观察点超出路线、地图被替换、照片越界和位姿非法时拒绝运行；
- left/right 路由、速度、末端减速、3 度对中和 JAKA 速度正确；
- pause/stop 与普通行驶、对中、机械臂观察之间不存在补发运动命令；
- `bash -n 9.18.sh`、Python 编译、`--dry-run` 和全量 pytest 通过。

硬件验收采用低风险首圈：手持实体急停，先观察路线接入、首个停车点减速、原地
对中、对应方向伸臂和安全收回。软件测试不能代替新地图上的实体净空确认。
