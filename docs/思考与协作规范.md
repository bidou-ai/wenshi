# 思考与协作规范

这是 Wenshi 每次开始任务时使用的固定检查表。

## 开始前

- 先阅读相关代码、配置、测试、数据和现行文档。
- 查看 `git status`，不覆盖、重置或删除用户已有的无关改动。
- 直接检查本机日志和数据，不让用户重复执行本机可以完成的命令。
- 判断任务是简单、一般还是复杂：简单任务不使用多智能体；复杂任务才并行。
- 共享文件按顺序处理，只有独立任务才并行。

## 实施时

- 先说明理解、影响范围、风险和验证方法；已确认的信息不重复询问。
- 需求变化后按最新需求处理，除非用户主动要求，不带回已结束旧需求。
- 代码修改先写失败测试，再实现，再回归验证。
- 原始数据必须保留，处理结果写入新目录；不覆盖原图。
- Tag 可作为以后正式身份确认的增强条件，但不能阻塞当前无 Tag 的训练采集。
- 整株模型和稻穗模型独立训练，类别分别为 `rice_plant` 和 `panicle`。
- 整株图像和稻穗图像分别判断方向、清晰度、遮挡、重复率和标注规则。

## 输出时

- 分开说明数据统计、代码测试、现场证据、未解决问题和需要确认的问题。
- “通过”必须有命令、日志或数据证据；否则写“未验证”或“建议”。
- 功能、配置、数据格式和现场状态变化时，同步更新唯一现行文档。
- `docs/` 下新 Markdown 使用中文名称，旧资料优先归档。
- 完成时给出文件路径、测试结果、可复制命令和下一步。
