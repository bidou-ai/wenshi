# Wenshi 株高与有效穗观测实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏现有 Wenshi rice 巡检和用户未提交修改的前提下，建立面向 24 株水稻、12 个逻辑停车位置、AprilTag 身份确认、三视角 RGB-D 采集、株高半自动复核、有效穗人工复核和 CSV 导出的表型观测基础。

**Architecture:** 新表型任务作为 `phenotype` 独立入口，由唯一高层控制器编排路线、停车、Tag、机械臂三视角采集和安全状态；Tag、采集存储、株高、有效穗、导出和后台复核模块不持有 AGV/JAKA 运动对象。新数据使用 `plants/<plant_id>/` schema，与旧 `targets/T*/far.jpg/near.jpg` 并行兼容。

**Tech Stack:** Python 3.10 标准库、现有 Wenshi AGV/JAKA/D435/ROS2 客户端、OpenCV/NumPy、现有 HTTP dashboard、pytest、YAML、浏览器原生 JavaScript。

**Spec:** `CODEX_PROJECT_BRIEF.md`

## Global Constraints

- 初期只做株高和有效穗数；花时、旧 rice 抵近、倒车、J5 跟随和 4D 展示保留但不进入本期主流程。
- 正式路线保持 `LM1 -> LM4 -> LM3 -> LM2`；不为 24 株创建 24 个 AGV 地图站点。
- 24 株采用 `A-01..A-06`、`B-L-01..B-L-06`、`B-R-01..B-R-06`、`C-01..C-06`；示例 Tag 映射只能用于测试，未确认时正式任务拒绝启动。
- 12 个停车位置采用 `left-01..left-06` 和 `right-01..right-06`；未填现场地图距离、触发距离和姿态时只能配置检查、模拟和单株采集测试。
- Tag 固定在对应水稻卡槽前方，朝上或侧放均可；Tag 离水面高度、物理尺寸、ID 映射、朝向和安装细节全部保持可配置，未标定值不得作为正式空间测量依据。
- 表型三视角默认 `left/center/right`，每视角默认保存 3 张、最多 5 张，选择最佳帧；单视角最多重拍 3 次，失败标记补采并继续。
- 表型流程底盘完全停稳后才允许机械臂动作，机械臂回安全姿态后才允许底盘继续；不得启用旧倒车、固定抵近和目标跟随。
- 计算模块不能控制 AGV/JAKA；算法失败只能返回 `needs_review`/`failed`，由总控制器决定重拍、补采、继续或停止。
- 所有 JSON 原子写入；媒体路径限制在运行目录内；后台默认本机/LAN，不开放公网。
- 现有工作区未提交修改必须保留；本轮先做软件、模拟和离线测试，不连接真实 AGV/JAKA/D435。
