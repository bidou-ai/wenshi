# Wenshi 预备工具与初步巡检 Demo 设计

## 状态

本设计已由用户确认，作为后续实施计划和代码修改的边界。`wenshi/yubei/`
是可删除的独立预备工具，不作为正式运行时依赖；正式 Demo 继续使用
`wenshi/app/wenshi_patrol` 的硬件和路线分层。

## 目标

完成一个可由人工看护运行的初步 Demo：沿 Wens1 温室路线循环发现完整水稻，
准确区分路线段、左右侧和前后顺序；发现目标后保存一张远景，底盘在受控抵近状态
低速后退，J5 实时跟随目标，执行对应侧的机械臂固定示教动作，保存一张近景，
然后恢复原方向巡检。后台在局域网展示本次巡检结果。

本阶段不实现花识别、手眼标定、地图坐标约 ±10cm、多个用户账号和公网服务。
这些后续事项写入 `wenshi/liuyi666.md`。

## 方案与边界

采用“在现有 Wenshi 控制框架上增加任务层”的方案：

- AGV、JAKA、D435、路线控制器和现有安全客户端继续作为硬件边界。
- 新增目标选择、目标跟随、抵近状态机、运行存储、质量检查和局域网后台。
- `yubei` 不导入正式控制器；它通过独立协议客户端或文件接口工作。
- AGV 只有正式路线状态使用正向运动；只有目标任务的 `ALIGN_REVERSE` 状态
  可使用低速后退。普通手动测试和路线状态不能借此获得倒车权限。
- JAKA 关节命令始终只有一个所有者：普通路线为 J5 巡视线程，目标跟随为跟随线程，
  固定抵近和回撤为示教动作线程。

## 正式巡检数据流

Windows D435 服务通过 HTTP 提供 RGB、对齐深度和健康状态。Ubuntu 相机桥将其
转换为 Wenshi 内部帧；视觉检测器在 RGB 上执行 rice 检测，并读取同步深度。
任务状态机消费稳定目标，向现有 AGV/JAKA 控制边界发送受限命令；所有结果写入
当前 `run_id`，后台只读取运行目录和索引。

### 状态流程

1. `PATROL_FORWARD`：循环执行 `LM1 -> LM4 -> LM3 -> LM2 -> LM1`。转弯及站点
   前后安全距离内不发起目标任务。
2. `TARGET_CONFIRM`：最近5帧中至少3帧出现有效 rice；从合格目标中选择 bbox
   中心最靠近画面中心者，锁定左/右侧，采集多帧深度。
3. `FAR_CAPTURE`：只写入该目标一张 `far.jpg`，并记录路线段、左右侧、沿路线位置、
   发现顺序、bbox、置信度和深度摘要。
4. `ALIGN_REVERSE`：暂停普通 J5 扫动，J5 根据 bbox 横向误差和深度实时跟随；
   AGV 以初始 0.05m/s 后退，单次硬上限 0.60m。车尾雷达未验证时只显示醒目提示，
   仍要求人工现场看护。目标丢失、相机断流、设备异常或人工停止立即停底盘。
5. `RELOCALIZE`：后退后重新确认目标和深度；失败时终止本次目标任务，恢复巡视姿态，
   沿正方向继续。
6. `FIXED_APPROACH`：根据已锁定的左/右侧执行 `camera_side -> side_pre -> side_photo`。
   仅允许 J4/J5/J6 在安全小范围内做构图修正，之后沿已知通道回撤。
7. `NEAR_CAPTURE`：近拍姿态内存连拍，最多3轮、每轮5张，只保存质量最高的一张
   `near.jpg`；若位置变化超过画面宽高8%或深度变化超过5cm，才重新执行抵近。
8. `RETRACT_AND_RESUME`：回到巡视姿态，恢复原方向巡检。

目标跟随期间目标侧别不自动切换；若目标横向误差超出安全范围，先停车重新确认。

## 目标与去重

一株定义为同一个栽植点长出的一个茎蘖丛。一个图片可有多个 rice bbox，轻微交叠
允许 bbox 互相重叠；严重交叠且无法确定归属的图片进入 `ambiguous`，不用于首版训练。
首版训练只使用主体和归属清楚、可见部分足够完整的图片。

初筛选择画面中心目标；选中目标周围30cm的目标只在当前圈暂缓，下一圈重新允许处理。
已拍目标按路线段、侧别、沿路线位置和发现顺序管理，2小时内去重；新 `run_id`
重新开始去重范围。初期不跨运行识别同一实体，地图坐标关联留到后续手眼标定。

## 照片与日志

每株只保存远景和近景各一张原始 RGB JPEG；不保存候选连拍、重复标框图或深度图片。
质量分数、目标框、深度统计和失败原因写入 metadata，后台动态绘制 bbox。

```text
runtime/runs/run_<timestamp>/
  run.json
  events.jsonl
  system.log
  targets/T0001/
    far.jpg
    near.jpg
    metadata.json
```

默认不自动删除。后台只在管理员 PIN 通过后允许软删除；操作手册提供预览后永久清理
指定历史运行的命令，并明确正在运行的目录不能清理。

## yubei 预备工具

```text
yubei/
  camera_check.py       # D435 HTTP/帧/解码/实时预览诊断
  network_check.py      # IP、端口、路由和服务连通性诊断
  device_check.py       # AGV/JAKA 状态和只读协议检查
  dataset_capture.py    # 回车保存 RGB JPG 的会话采集
  label_server.py       # 本地网页 bbox 标注
  dataset_validate.py   # YOLO 目录、类别、框和划分检查
  train_yolo.py         # 首版 rice 训练入口
  publish_model.py      # 模型复制并校验到正式 models/
  teach_viewpoints.py   # 8个机械臂姿态读取/保存/验证
  viewpoint_verify.py   # 路径跨度、回撤通道和顺序检查
  README.md
  TRAINING.md
  ANNOTATION_GUIDE.md
```

类别固定为 `rice=0`、`flower=1`，首版只训练 rice。采集数据和正式巡检运行目录
完全分离；yubei 删除不会影响已发布到 `wenshi/models/` 的模型。

## 后台

后台只绑定温室局域网，初版无用户账号。普通访问者可查看当前和历史运行、目标计数、
路线段、左右侧、远近图片、动态 bbox、质量分数和失败原因；管理员 PIN 才能执行
软删除、去重重置和历史清理。后台不提供运动控制。

## 暂缓问题

`wenshi/liuyi666.md` 记录：三个种植区域与路线的精确对应、手眼标定和 ±10cm 地图坐标、
严重交叠样例、花识别的近景阶段、GPU/VM 方案和后续跨运行目标关联。

## 验收方向

- 离线测试集 rice precision 和 recall 目标均不低于95%。
- 现场连续三圈不发生误抵近，完整可见水稻漏检率目标不超过5%。
- 目标任务中 J5 跟随、底盘后退、固定示教和回撤均有独立停止条件和日志。
- D435 断流、目标丢失、AGV/JAKA 异常和管理员清理均有可测试的失败路径。
