# 有效穗候选与人工复核

本模块只处理有效穗候选及复核数据，不连接 AGV、JAKA、D435，也不负责运行模型。模型或离线脚本输出三视角候选后，由 `effective_panicles.py` 统一规范化并供后台复核使用。

## 数据与状态

每个候选包含 `candidate_id`、`view`、`bbox`、可选 `score`、`status` 和可选 `panicle_group_id`。状态固定为：

- `confirmed`：人工确认是有效穗
- `suspected`：自动候选但尚未确认
- `occluded`：被遮挡，暂不能判断
- `duplicate`：与其他候选重复
- `deleted`：人工删除，不计入活动候选

候选保留来源视角和原始框，任何人工操作都会写入 `history`，便于追溯。

## 跨视角复核

同一穗在多个视角出现时，调用 `merge_panicles()` 为候选设置同一个 `panicle_group_id`。误合并时调用 `split_panicle()`，将一个组拆成两个或多个组。只想解除关联而不删除候选时使用 `unmerge` 操作。人工遗漏可用 `add_panicle()` 新增，误检使用 `delete`，状态修正使用 `status` 操作。

三视角可以先分别标注，再按组复核。模块不会依据空间距离擅自合并候选，跨视角合并必须由人工或上层明确提供关系。

## 统计口径

`automatic_count` 是模型或自动候选数量，`reviewed_count` 是人工最终确认数量，`difference = reviewed_count - automatic_count`。状态计数和活动候选计数用于解释差异；`group_count` 统计未删除的跨视角组。

正式有效穗数量以人工 `reviewed_count` 为准，自动数量只作对照，不能自动放行正式结果。

## 示例

```python
from wenshi_patrol.phenotyping.effective_panicles import (
    PanicleReview, build_candidates, merge_panicles, summarize_panicles,
)

review = PanicleReview(build_candidates("A-01", {
    "left": [{"bbox": [10, 20, 40, 90], "score": 0.86}],
    "center": [{"bbox": [14, 22, 44, 92], "score": 0.79}],
}))
merge_panicles(review, ["left-001", "center-001"], "panicle-001")
summary = summarize_panicles(review, automatic_count=2, reviewed_count=1)
```
