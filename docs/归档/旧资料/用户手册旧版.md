# 用户手册

## 1. 用途

本期系统观测 24 株水稻的株高和有效穗数，使用 12 个逻辑停车位置，每株保存 `left`、`center`、`right` 三视角 RGB-D 证据，人工复核后形成正式值。

本期不做花时、颖壳张角、柱头指标、穗粒数、破坏性取样或 3D/4D 展示。仓库中的 flower、rice、倒车、J5跟随和固定抵近内容是旧原型。

现有正式 rice 入口的固定路线为 `LM1 -> LM4 -> LM3 -> LM2`；这条旧原型路线与本期尚未接入的 12 位置表型编排是两个边界，不应混用。

## 2. 现场准备

```bash
cd /home/ubuntu/jaka/wenshi
./scripts/start_field_test.sh --no-rviz
```

`teach` 时人工移动到提示点，按回车读取保存，程序自动进入下一点且不发送运动命令；`test arm` 才逐点运动。验证后发布示教点：

```bash
./yubei/start_yubei.sh verify
./yubei/start_yubei.sh publish-viewpoints --confirm
```

## 3. 配置放行

完成并复核 `config/wenshi.yaml` 中的 24 个 Tag 映射、`april_tag.physical_size_m`、`detector_backend`、`mounting_orientation`、每株或区域水面补偿、12 个位置参数、独立表型姿态和相机标定。Tag 固定在相应水稻的卡槽前，可以朝天或侧放；朝向必须明确记录，距离水面的高度当前未知，不能猜测。

`./scripts/start_wenshi.sh phenotype` 在资料不全时应拒绝启动。只有现场证据齐全后才讨论正式运动流程。

## 4. 复核口径

株高沿卡槽/水面基准、同一根茎秆中心线、穗轴到最高穗顶计算三维弧长，再加水面补偿；不能使用画面最高点或直线距离。保存自动路径、自动值、人工路径、人工值和差值。

有效穗先逐视角记录候选，再合并同一穗。状态为 `confirmed`、`suspected`、`occluded`、`duplicate`、`deleted`；允许人工新增、删除、合并和拆分，最终以 `reviewed_value` 为准。

## 5. 后台

```bash
./scripts/start_dashboard.sh
```

访问 `http://127.0.0.1:8088/`。当前表型 API：

```text
GET /api/phenotype/runs
GET /api/phenotype/runs/<run_id>
GET /api/phenotype/runs/<run_id>/plants/<plant_id>
GET /api/phenotype/runs/<run_id>/plants/<plant_id>/media/<view>/<file>
GET /api/phenotype/export/<run_id>
```

后台当前为只读查看和 CSV 导出，不是运动控制端，也没有浏览器编辑接口。运行日志和数据位于 `runtime/runs/`；现场测试记录位于 `runtime/field_tests/`。

旧正式运行的关键日志包括 `events.jsonl`、`agv.csv`、`jaka.csv`、`camera.log` 和 `console.log`。Windows D435 可双击 `start_camera_server.bat`，或运行 `py windows_realsense_server.py --host 0.0.0.0 --port 18080`。管理员 PIN 只用于旧管理功能，不用于表型测量复核：

```bash
WENSHI_ADMIN_PIN='现场设置的PIN' ./scripts/start_dashboard.sh
```

未配置 `WENSHI_ADMIN_PIN` 时，查看功能仍可用，管理操作保持关闭。SSH/ToDesk 只用于维护或观察，不改变后台默认的 `127.0.0.1` 监听边界。
