# Phenotyping Data Schema

表型观测与旧版 `targets/T*` 巡检结果并行保存。后台只读接口不会启动 ROS2、AGV、JAKA 或相机。

## Run layout

```text
runtime/runs/run_<timestamp>/
  run.json
  events.jsonl
  agv.csv
  jaka.csv
  plants/<plant_id>/
    plant.json
    review.json
    captures/{left,center,right}/
      color.jpg
      depth.png                 # 可选
      frame.json
    traits/plant_height.json
    traits/effective_panicle_count.json
```

`plant.json` 保存株号、Tag、区域、行、停车组、采集状态和三视角状态。`frame.json` 保存该帧的时间、设备元数据、质量和 Tag 证据；深度不可用时明确为 `null`，不伪造数值。

两个 trait 文件同时保留自动候选值、人工复核值、差值、状态和原因。正式结果以 `reviewed_value_m` 或 `reviewed_value` 为准；没有复核时保持 `null`。

## Read-only API

- `GET /api/phenotype/runs`
- `GET /api/phenotype/runs/<run_id>`
- `GET /api/phenotype/runs/<run_id>/plants/<plant_id>`
- `GET /api/phenotype/export/<run_id>`

所有 ID 都限制为单一路径组件并解析到 runtime 根目录内。非法或不存在的批次/株号返回错误，不会读取根目录外文件。旧的 `/api/runs`、`/api/runs/<run>/targets/...` 和管理员接口保持原有行为。

## CSV

导出为 UTF-8 CSV，首行列顺序固定。字段包含批次、株号、Tag、位置、三视角完成状态、株高自动/人工/差值、有效穗自动/人工/差值、质量、复核状态、原因和媒体链接。空值输出为空字符串，嵌套字段使用无空格 JSON，避免丢失证据结构。
