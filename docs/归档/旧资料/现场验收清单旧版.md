# Wenshi 现场测试清单

按顺序执行，每一步通过后才进入下一步。任何报警、急停、人员进入运动区、姿态异常或通信中断，先实体急停，再输入 `stop`。未测量内容填写“未验证”。

## 1. 离线入口

```bash
cd /home/ubuntu/jaka/wenshi
./scripts/start_wenshi.sh --help
./scripts/start_field_test.sh --help
./yubei/start_yubei.sh --help
./scripts/start_dashboard.sh --help
PYTHONPATH=app:. python3 -m pytest -q
```

## 2. 网络、相机和 Tag

启动 Windows D435 的 `start_camera_server.bat`，或 `py windows_realsense_server.py --host 0.0.0.0 --port 18080`，再执行 `./yubei/start_yubei.sh camera-check`。确认 `/health`、连续帧、RGB/深度尺寸和时间戳。AGV、JAKA、相机电脑留在机器人内网，Ubuntu 的另一条路径连接公网。

逐株记录 Tag ID、株号、实际边长、方向（`upward`/`side`）、卡槽前位置、Tag 到卡槽/水面的高度和可见性。family 固定为 `tag25h7`，不要假设当前 OpenCV 支持该 family。完成前配置保留 `null`，正式预检应失败。

## 3. JAKA 和路线

```bash
./scripts/start_field_test.sh --no-rviz
```

在 `field>` 执行 `teach`、`test arm`、`test route`。`teach` 依次保存八个点，每次回车后自动进入下一个；`test arm` 才运动且底盘必须停止。`test route` 验收正向路线 `LM1 -> LM4 -> LM3 -> LM2 -> LM1`，不应出现倒车。

八个示教点必须包含 `home_safe`。旧 rice 抵近相关的 `target_reverse_limit_m`、`rear_radar_verified` 和固定抵近路径不属于表型采集放行条件；这些安全项未验证时，不得启用完整视觉抵近。

## 4. 12 位置和三视角

左通道记录 `left-01` 到 `left-06`，覆盖左区和中间左排；右通道记录 `right-01` 到 `right-06`，覆盖中间右排和右区。每个位置记录路线段、沿线距离、减速距离、Tag 触发距离、停车误差和两株身份。未完成标定不能启用表型正式运动。

选一处位置的两株，底盘停稳后逐一验证 `left`、`center`、`right` 姿态、RGB-D 同步、Tag 唯一绑定、图像质量和 `frame.json`。失败视角重试，超过上限标记补采。再扩展到 12 位置并核对 24 株覆盖。

## 5. 测量和后台

为每株保存人工株高和有效穗对照。株高沿同一茎秆、穗轴到最高穗顶量取；有效穗不能把三视角直接相加，必须合并后人工确认。启动 `./scripts/start_dashboard.sh`，确认 `http://127.0.0.1:8088/` 可查看运行、单株、媒体、状态并导出 CSV。

## 6. 禁止事项

- 未完成 Tag、停车、姿态、相机和补偿标定，不启用 `phenotyping.enabled`。
- 不启用 `vision.enabled`、`patrol_target.enabled` 或 `fixed_approach.enabled` 代替表型功能。
- 不使用旧花时/rice 抵近、倒车、J5 跟随或 `far/near` 结构作为本期结果。
- 不把离线测试通过写成硬件或测量精度现场通过。
