# Wenshi 架构

## 1. 目标和边界

本期表型任务只覆盖株高和有效穗数。系统面向 24 株水稻、12 个逻辑停车位置和每株三视角 RGB-D 采集。Tag 用于身份确认、局部位置和尺度参考，不承担整条路线导航。

当前代码已经提供表型配置 schema、Tag 检测适配器、可恢复的单株存储、株高弧长计算、有效穗候选复核模型和只读后台 API。表型模块尚未成为 `patrol_controller.py` 的正式运动编排流程。

## 2. 分层

| 层 | 代码 | 责任 |
|---|---|---|
| 硬件客户端 | `agv.py`、`jaka.py`、`camera_bridge.py` | TCP/ROS2 状态和数据访问 |
| 路线与安全 | `route_controller.py`、`control/`、`hardware_check.py` | 地图路线、限速、状态新鲜度和安全互锁 |
| 旧巡检编排 | `patrol_controller.py` | 当前正式 rice 原型的唯一 AGV/JAKA 高层控制点 |
| 视觉基础设施 | `vision/` | 帧新鲜度、质量、RGB-D 几何、旧目标存储 |
| 表型数据层 | `phenotyping/schema.py`、`capture_schema.py`、`plant_store.py` | 配置、单株目录、原子写入和恢复 |
| 表型算法层 | `tag_adapter.py`、`plant_height.py`、`effective_panicles.py` | 身份判断、株高候选、有效穗候选和人工操作记录；无运动权限 |
| 后台 | `dashboard/` | 表型运行只读查看和 CSV 导出；不持有硬件对象 |

只有高层控制器可以同时持有 AGV 和 JAKA。表型算法、存储和后台不得发送运动命令；算法失败只能产生 `needs_review`、缺失或失败状态。

## 3. 表型运行模型

```text
启动预检 -> 接近下一个 12 位置 -> 识别预期 tag25h7 Tag -> 底盘停稳
-> 两株各采 left/center/right -> 保存 RGB-D、帧和硬件快照
-> 株高路径候选 -> 有效穗候选及跨视角去重 -> 后台人工复核和导出
```

上图中的正式运动编排仍待实现。路线仍为 `LM1 -> LM4 -> LM3 -> LM2`，普通路线不因表型算法任意倒车。12 个位置的路线段、沿线距离、减速距离和触发距离当前为 `null`。

## 4. 数据和旧原型

表型主数据使用 `plants/<plant_id>/captures/<view>/`，不使用旧 `targets/T*/far.jpg/near.jpg`。JSON 和媒体写入使用原子替换，路径校验拒绝穿越。Tag 检测通过独立适配器接入，不匹配时不得猜测株号。

`patrol_target_runtime.py`、`target_task.py`、`target_follow.py`、`near_capture.py`、`fixed_approach.py` 和 `TARGET_*` 状态属于旧 rice 目标抵近原型，不是本期花时或表型实现。
