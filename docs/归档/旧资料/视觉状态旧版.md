# 视觉状态

## 本期表型

本期只做株高和有效穗数。株高从卡槽/水面基准沿同一根茎秆、穗轴到最高穗顶计算三维路径弧长；存储单位为米。有效穗统计能够看清并确认已经长出的穗子，三视角候选必须跨视角合并，最终数值以人工确认值为准。

每株计划使用 `left`、`center`、`right` 三视角。缺视角或深度无效时保留证据并进入复核/补采状态。

## 已有能力

`phenotyping/plant_height.py` 已实现 3D 折线弧长、补偿优先级、范围和有限数检查，并在遮挡、路径歧义、深度不足或补偿缺失时输出 `needs_review`。`effective_panicles.py` 已实现候选状态、跨视角分组、人工合并/拆分/新增/删除和计数差异。两者都不连接相机、机器人或模型。

`tag_adapter.py` 只接受 `tag25h7`，通过可配置 backend 产生规范化检测结果。Tag 不匹配、缺失、重复或预期 ID 未配置时不能猜测身份。

## 尚未具备

- 没有已发布的有效穗模型。
- 没有正式表型采集控制器、三视角机械臂姿态或 12 位置触发逻辑。
- Tag ID、尺寸、朝向和距离水面的高度未标定。
- 相机内参、深度尺度、RGB-D 对齐、手眼标定和株高精度未现场验收。

旧 `vision/` 中的 rice YOLO、目标跟随、受控后退、固定抵近和远近景代码是旧目标抵近原型，不等于花时识别，也不属于本期表型流程。
