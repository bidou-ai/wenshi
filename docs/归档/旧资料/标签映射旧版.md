# AprilTag Mapping and Field Verification

The phenotyping task uses `tag25h7` for plant identity and local trigger
confirmation. The adapter keeps the detector backend configurable because the
known Windows OpenCV environment does not provide a guaranteed
`DICT_APRILTAG_25h7` constant. No OpenCV dictionary is assumed by this
project.

## Installation and mounting

Each plant receives one Tag fixed in front of its corresponding planting slot.
The Tag may face upward or be mounted on the side. Record the actual
`mounting_orientation` as `upward` or `side`; use `unknown` until it is
verified. The Tag height above the water surface is currently unknown and
must remain a field-calibration value. It must not be inferred from the image
or used for formal spatial measurement before calibration.

Record these values for every installed Tag:

- printed Tag ID;
- stable plant ID and observation group;
- physical square size in metres;
- mounting orientation and approximate height above water;
- visibility, tilt, and any expected occlusion.

The original Windows path `D:\my gz\tag\tag` is only a resource reference;
it is not used by the code. Import the final mapping through the project
configuration after the physical installation has been checked.

## Non-formal example mapping

This example is for fixtures, tests, and interface development only. It is
not the formal field mapping:

```text
0-5    -> A-01 .. A-06
6-11   -> B-L-01 .. B-L-06
12-17  -> B-R-01 .. B-R-06
18-23  -> C-01 .. C-06
```

The formal task must reject incomplete or unverified IDs, physical size,
orientation, and slot-to-water measurements. AprilTag confirms local plant
identity and trigger state; AGV map progress remains responsible for coarse
route positioning. Do not create 24 AGV map stations.

## Offline verification

Unit tests inject a deterministic fake backend and verify normalization,
duplicate-ID rejection, expected/mismatched/missing decisions, and mounting
metadata. These tests do not establish physical camera accuracy. Before field
use, validate the selected backend on the target Ubuntu/Windows environment
with printed `tag25h7` images, then record the backend version and a real
camera decode report.
